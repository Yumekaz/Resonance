./data/review-fixed.exe -addr 127.0.0.1:8080 -media data/demo.wav

## Method and results

The HTTP harness performs HEAD, consumes one full GET, consumes a first 64 KiB range, then consumes 100 seeded random ranges of up to 64 KiB (clipped at EOF). Seed 42, sequential requests, one Go client with connection reuse. No deliberate HTTP warm-up phase or network impairment; OS cache state is uncontrolled and the full read warms the subsequent range workload. Each response must match expected status, Content-Range, Content-Length, and consumed byte count. An invalid response aborts the run rather than producing a successful report. The harness does not benchmark error rates or validate audio decoding.

TTFB ends on receipt of the first body byte, not receipt of headers. Total time includes consuming the body. Median averages the middle pair; p95 uses rank ceil(0.95*N). The raw report includes all 102 samples, request IDs, actual lengths, statuses, and range headers.

| Metric | Independent run |
|---|---:|
| Full GET TTFB, one sample | 3.3116 ms |
| First range TTFB, one sample | 2.9872 ms |
| Random range TTFB median / p95, 100 samples | 2.9571 / 3.8995 ms |
| Random range total median / p95, 100 samples | 3.0116 / 3.9640 ms |

This is a baseline, not an optimization comparison or a latency SLO.

## Browser evidence

The browser run disables cache and applies 256 KiB/s download throughput and 20 ms latency using Chromium network emulation. It observes media bytes through CDP rather than treating the decoded `buffered` timeline as transfer accounting.

- Playback advanced after 494,306 of 26,460,044 media bytes arrived (about 1.87%).
- Seek target: 210 seconds, explicitly outside all buffered intervals.
- A new request issued after the seek listeners were installed used `Range: bytes=18513920-`.
- Response: `206`, `Content-Range: bytes 18513920-26460043/26460044`, with matching Content-Length.
- A `playing` event followed, and currentTime advanced past target + 0.2 seconds with seeking complete.
- Seek-action-to-playing event: 189.9 ms, one sample. This includes test action dispatch and user-level resume; it is not physical audible output, a percentile, or directly comparable with HTTP TTFB.

Evidence: `M0-review-browser.json` and `M0-review-browser-server.jsonl`. Server logs independently show incomplete transfers canceled when the browser seeks/closes, with accepted byte counts much smaller than the full media. Accepted server writes and browser-received bytes intentionally differ.

## Original evidence retained

`M0-raw.json` is preserved unchanged as the implementation agent's original run. Its full/first-range TTFB values are 6.9342/3.5549 ms. Its reported total median 4.0000 ms selected the upper middle sample; the conventional median recomputed from those original samples is 3.9955 ms. Its p95 4.8906 ms agrees with nearest rank. The original browser check was weaker: it accepted nonzero ranges from anywhere in the test and used buffered duration as a transfer proxy. Its 316 ms result is not retained as strong seek-retrieval evidence.

## Limits

No phone/LAN measurement, acoustic output measurement, maximum-concurrency claim, or large-file memory profile. Windows junction containment passed; a file-symlink regression skipped due to missing symlink privilege. Race detection could not run because the installed Go toolchain has CGO disabled and no C compiler was available on PATH. These omissions are not reported as passes. A 256 MiB sparse-file disconnect test verifies cleanup, not constant process memory.
