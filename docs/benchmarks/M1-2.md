# M1.2 initial import baseline

## Environment and configuration

- Run date: 2026-09-21; timestamp `2026-09-21T01:08:43.3517273Z`.
- Windows_NT 10.0.26200 x64; AMD Ryzen 7 5700U; 16 logical CPUs; 16.47 GB RAM.
- Go 1.25.0; PostgreSQL 17.11 on loopback port 55432 with `max_connections=20`; application pool maximum four connections.
- One Resonance scan process and one Resonance HTTP server process on the same laptop. Scanner file buffer: 32 KiB. The M0 server streamed the generated 26,460,044-byte WAV.
- Corpus: 300 copies of an explicitly CC0 MP3 with distinct generated ID3v1 tags, one CC0 FLAC, and one generated one-second PCM WAV. Total: 302 files and 795,948,098 bytes. Corpus generation is reproducible with `tools/m1-2-corpus.ps1` plus `cmd/fixture`.
- Warm local filesystem/OS cache may materially favor this run. No network filesystem or phone was involved.

## Commands

The exact setup and commands are documented in `docs/runbooks/M1-2-library.md`. The measured command was:

```powershell
pwsh -NoProfile -File tools/m1-2-benchmark.ps1 `
  -RootId 52358719-ba61-48fe-b424-dfce6b6b4292 `
  -ServerExe data/m12-server.exe `
  -BenchExe data/m12-bench.exe `
  -PgBin data/postgresql-17.11/pgsql/bin `
  -OutputPrefix docs/benchmarks/M1-2
```

The script first measured 100 idle random 64 KiB Range requests. It then started the initial scan and measured another 100 Range requests while the scan process was alive. The HTTP benchmark and scan overlap was 577 ms.

Independent recalculation from the 100 raw random-Range samples reproduced both medians and p95 values exactly. Nearest-rank p99 was 4.1284 ms idle and 4.8316 ms concurrent. The file count and byte total also match the retained 302-file corpus.

All Range requests passed status, `Content-Range`, `Content-Length`, and consumed-byte validation. These measurements establish a local baseline and no hard threshold. The observed concurrent p95 was 0.6006 ms above idle p95, but one loopback run does not establish causation or production behavior.

Raw/machine-readable artifacts are `M1-2-summary.json`, `M1-2-scan-result.jsonl`, `M1-2-scan-log.jsonl`, `M1-2-idle-playback.json`, and `M1-2-concurrent-playback.json`. They contain logical IDs and measurements, with no database password or absolute media path.

## Limits

- The corpus emphasizes hashing and many MP3 imports; it is not representative of every personal library's file sizes, tags, directories, disk, antivirus, or cold-cache behavior.
- Process peak memory and CPU were sampled by PowerShell, not captured by a continuous profiler. PostgreSQL resource use was not isolated.
- The metadata extraction count records attempts, not a claim that every file had complete tags.
- Playback concurrency was measured through HTTP Range requests. Browser seek behavior remains covered by the separate M0 Playwright regression and was not conflated with this HTTP benchmark.
- The PostgreSQL size includes existing development rows in the measured database. Use a fresh database to isolate schema and corpus size precisely.
- The retained summary records a script-derived 577 ms process overlap, while the scan JSONL timestamps and concurrent report completion timestamp corroborate that playback ran during the scan. The original artifacts do not retain all four high-resolution process boundary timestamps, so the exact 577 ms value cannot be reconstructed independently; the benchmark script now preserves those boundaries for future runs.
