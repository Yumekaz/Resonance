# M1.6 watcher, recovery, and overlap measurements

Run date: 2026-09-25. Host: Windows amd64, 16 logical CPUs, Go 1.25. PostgreSQL 17.11 on loopback used `shared_buffers=128MB`, `fsync=on`, and `synchronous_commit=on`. Each integration run used isolated schemas on a dedicated local test cluster. Caches were warm and not reset. Percentiles were independently recalculated from raw samples: p50 averages the two middle values for even sample counts; p95/p99 use nearest rank. These are local baselines, not SLOs.

## Watcher-to-authoritative-scan convergence

Command:

```powershell
$env:RESONANCE_TEST_DATABASE_URL = '<dedicated local PostgreSQL test database>'
$env:RESONANCE_M16_BENCHMARK_OUTPUT = (Join-Path (Resolve-Path docs/benchmarks).Path 'M1-6-watcher-convergence.json')
go test -p 1 -parallel 1 -tags=integration -run TestM16BenchmarkWatcherConvergence -count=1 ./internal/library
```

Thirty samples started when a small text marker was written to an otherwise empty verified root and ended after the event-triggered scan committed with `traversal_complete=true` and `absence_reconciled=true`. Each marker was deleted and its following authoritative scan completed before the next sample.

| Samples | p50 ms | p95 ms | p99 ms |
|---:|---:|---:|---:|
| 30 | 903.293 | 1,014.468 | 1,025.927 |

The 750 ms debounce is visible in this result. The sample includes filesystem notification delivery, debounce, traversal, PostgreSQL publication, and test polling. It measures an empty root and does not represent a large music library. [Raw samples and environment](M1-6-watcher-convergence.json).

## Indexed Range requests during queue reorders

Command:

```powershell
$env:RESONANCE_TEST_DATABASE_URL = '<dedicated local PostgreSQL test database>'
$env:RESONANCE_M16_RANGE_BENCHMARK_OUTPUT = '<absolute path to a fresh output file>'
go test -p 1 -parallel 1 -tags=integration -run TestM16BenchmarkIndexedRangeDuringUserLibraryWrite -count=1 .
```

Thirty pairs sent an HTTP `206` for a 4 KiB indexed WAV Range and an HTTP queue reorder over 1,000 queue occurrences through a local HTTP server. Client timestamps show actual request intervals; all 30 pairs overlapped. Percentiles were independently recalculated from both request streams.

| Request | p50 ms | p95 ms | p99 ms |
|---|---:|---:|---:|
| Indexed Range | 9.589 | 15.812 | 17.130 |
| Queue reorder request | 352.071 | 514.734 | 549.424 |

These timings are end-to-end local request durations, not direct database lock-duration measurements. The queue result is nontrivial, but it showed no correctness failure and does not establish a latency SLO. [Raw paired timestamps and overlap checks](M1-6-range-write-overlap.json).

## Limits

The user-library workload repeats one Track ID, the Range workload uses one small local WAV, and the convergence workload uses one empty root with text markers. All are warm-cache, single-host, loopback tests; they do not model a large library, a phone connection, or cold storage. The measurements support regression checks only; no SLO is claimed.

Independent review recalculated the raw convergence, Range/write, and user-library percentiles and confirmed all 30 Range/write pairs overlap at request level. The convergence harness ends each sample after the scanner has returned a committed run with both authority flags, then the test observes the coordinator's success counter. Deterministic tests now exercise a 10,000-event storm, the 256-root dirty cap, the 4,096-directory watch cap, epoch follow-ups, watcher channel loss and recovery, periodic scans without events, shutdown cancellation, and a watcher-triggered 1,000-location/900-removal incomplete traversal. These are correctness tests, not measured idle overhead. This evidence set does **not** contain sampled idle CPU, watcher memory, or watch-handle count over a sustained interval; those remain unmeasured.
